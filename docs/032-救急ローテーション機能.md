## 2. データベース設計

### 2.1 新規テーブル：`emergency_rotations`

```sql
CREATE TABLE emergency_rotations (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  duty_date       date NOT NULL,                       -- 当番日（例: 2026-06-07）
  rotation_type   text NOT NULL CHECK (rotation_type IN (
                    'night_emergency',                 -- 夜間急患診療所（365日固定）
                    'duty_doctor',                     -- 休日当番医
                    'duty_dentist',                    -- 休日当番歯科
                    'duty_pharmacy'                    -- 休日当番薬局
                  )),
  area            text NOT NULL,                       -- '飯田地区' / '阿南地区' 等
  department      text,                                -- '内科' / '小児科' / '外科' / '産婦人科' / '歯科' / NULL（薬局・夜間急患）
  hospital_id     uuid REFERENCES hospitals(id) ON DELETE SET NULL,  -- 既存病院マスタとの紐付け（任意）
  facility_name   text NOT NULL,                       -- 表示用施設名（hospitals に無い施設もあるため必須）
  phone           text NOT NULL,                       -- 電話番号
  start_time      time NOT NULL,                       -- 例: 09:00:00
  end_time        time NOT NULL,                       -- 例: 18:00:00
  note            text,                                -- '11時までの電話予約者のみ' 等
  source_month    text NOT NULL,                       -- '2026-06' 形式（インポート単位の管理用）
  created_at      timestamptz DEFAULT now(),
  updated_at      timestamptz DEFAULT now()
);

CREATE INDEX idx_emergency_rotations_duty_date ON emergency_rotations(duty_date);
CREATE INDEX idx_emergency_rotations_type_date ON emergency_rotations(rotation_type, duty_date);
CREATE INDEX idx_emergency_rotations_source_month ON emergency_rotations(source_month);

-- RLS
ALTER TABLE emergency_rotations ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Public can read emergency_rotations"
  ON emergency_rotations FOR SELECT
  TO anon, authenticated
  USING (true);

-- INSERT/UPDATE/DELETE はポリシー無し → service_role 経由のみ（管理画面から）

-- updated_at は Server Action 側で手動更新する（既存テーブルと同じパターン）
--   例: .update({ ..., updated_at: new Date().toISOString() })
-- DB トリガーは導入しない（既存実装と統一）
```

### 2.2 マイグレーションファイル

| 項目 | 内容 |
|------|------|
| ファイル名 | `20260527000000_create_emergency_rotations_table.sql` |
| 命名規則 | 既存マイグレーション（`20260330084834_extend_hospitals_table` 等）と同じ |
| 実行方法 | Supabase MCP または `supabase db push` |

### 2.3 設計上の注意

| 項目 | 説明 |
|------|------|
| `hospital_id` が NULL 可能な理由 | 当番医に「へき地診療所」「薬局」など `hospitals` テーブルに登録されていない施設が含まれるため。表示用には `facility_name` を使う |
| `department` が NULL 可能な理由 | 薬局・夜間急患診療所は科の概念がない |
| `source_month` の用途 | 月単位の全削除・再インポートを安全に行うため。`WHERE source_month = '2026-06'` で絞り込みやすい |
| `duty_date` インデックス | 「今日の当番医」クエリの主要パス。最頻アクセス |
| **一意制約なし** | 同日・同種別・同地区・同科に複数施設が当番として並列するケースを許容するため、複合 UNIQUE は設けない。例：阿南地区 6/14 は県立阿南病院＋新野へき地診療所が同時担当 |
| `area` を自由入力にする理由 | 「飯田地区」「阿南地区」のような医師会区分（自治体マスタ `ALL_CITIES` とは粒度が異なる）と、自治体名（例：「平谷村」）が混在しうるため。マスタ化せずテキスト保存とする |
| 既存 `hospitals.emergency_available` との関係 | 別概念。`emergency_available=true` は「常時救急受入可」を示す病院属性、本テーブルは「持ち回り当番」を示すスケジュール。両者は独立して保持する |
| `updated_at` の更新方式 | DB トリガーは置かず、Server Action 内で `updated_at: new Date().toISOString()` を毎回明示する（既存テーブル全テーブルと統一） |

**処理フロー**:
1. ファイル受信 → papaparse / xlsx でパース
2. バリデーション（全行チェック、エラーがあれば中断してエラー一覧表示）
3. 確認ダイアログ：「2026-06 のデータを上書きします。XX件 → YY件」
4. `WHERE source_month = '2026-06'` で既存全削除
5. バッチINSERT
6. Toast通知 + 一覧へリダイレクト

**バリデーション**:
- `duty_date` がフォームの「対象月」と一致するか
- `rotation_type` が4種のいずれか
- `start_time` / `end_time` が時刻形式
- `phone` が NULL でない
- `facility_name` が NULL でない
- 既存 `hospitals` テーブルから `facility_name` 完全一致で `hospital_id` を自動付与（マッチしなければ NULL）

### 3.5 夜間急患診療所 月次自動生成画面（`/admin/emergency-rotations/generate-night`）

**目的**: 夜間急患診療所（365日対応）の1ヶ月分（30〜31日分）を一括生成する。

**画面構成**:

```
┌─────────────────────────────────────────────────┐
│ 夜間急患診療所 月次データ自動生成              │
├─────────────────────────────────────────────────┤
│ 対象月: [2026-06 ▼]                            │
│                                                 │
│ 施設情報:                                       │
│ 地区:    [飯田地区]                            │
│ 施設名:  [飯田市休日夜間急患診療所]            │
│ 電話:    [0265-23-3636]                        │
│ 昼間開始: [09:00] 終了: [12:30] (休日のみ)    │
│ 夜間開始: [19:00] 終了: [22:00] (365日)       │
│ 備考:    [受付 午後9時30分まで]                │
│                                                 │
│ ⚠️ 同じ月の夜間急患データは上書きされます      │
│                                                 │
│ [生成実行]                                      │
└─────────────────────────────────────────────────┘
```

**処理フロー**:
1. 対象月の1日から月末までの日付を生成
2. 既存の `WHERE source_month = ? AND rotation_type = 'night_emergency'` を削除
3. 各日付について以下を生成：
   - **夜間（19:00-22:00）**: 全日（365日）
   - **昼間（09:00-12:30）**: 休日（日曜・祝日）のみ
4. バッチINSERT
5. Toast通知

**祝日判定**:
- ライブラリ：`@holiday-jp/holiday_jp`（npm）または `japanese-holidays`
- 既存 `package.json` に追加が必要
- 振替休日も対象に含める

**生成例（2026-06、30日分）**:
- 夜間枠：30レコード（毎日19:00-22:00）
- 昼間枠：日曜（6/7, 6/14, 6/21, 6/28）の4日分 + 祝日なし
- 合計：34レコード

## 4. Server Actions（`src/app/admin/actions.ts` に追加）

既存の Server Actions と同じパターン。全関数で先頭に `await verifyAdminAuth()` を実行。

| 関数 | 役割 |
|------|------|
| `createEmergencyRotation(formData)` | 1件新規登録 |
| `updateEmergencyRotation(id, formData)` | 1件更新 |
| `deleteEmergencyRotation(id)` | 1件削除 |
| `importEmergencyRotations(formData, sourceMonth)` | CSV/Excel一括インポート（対象月の既存削除 → バリデーション → バッチINSERT） |
| `deleteRotationsByMonth(sourceMonth)` | 指定月の全データ削除 |
| `generateNightEmergencyRotations(sourceMonth, facilityInfo)` | 夜間急患診療所の月次データ自動生成 |
| `getEmergencyRotationsByMonth(sourceMonth)` | 月別取得（一覧画面用） |
| `getAvailableSourceMonths()` | 登録されている `source_month` の一覧取得（タブ表示用） |

**実装例（`generateNightEmergencyRotations`）**:

> `verifyAdminAuth()` は既存 `src/app/admin/actions.ts` 内のローカル関数を利用（lib への抽出はしない、既存パターン踏襲）。

```typescript
'use server';

// verifyAdminAuth は同ファイル内のローカル関数を利用
import { supabaseAdmin } from '@/lib/supabase-admin';
import { isHoliday } from '@holiday-jp/holiday_jp';

type NightFacilityInfo = {
  area: string;
  facilityName: string;
  phone: string;
  dayStart: string;    // '09:00'
  dayEnd: string;      // '12:30'
  nightStart: string;  // '19:00'
  nightEnd: string;    // '22:00'
  note?: string;
};

export async function generateNightEmergencyRotations(
  sourceMonth: string,
  info: NightFacilityInfo
) {
  await verifyAdminAuth();

  // 1. 既存削除
  await supabaseAdmin
    .from('emergency_rotations')
    .delete()
    .eq('source_month', sourceMonth)
    .eq('rotation_type', 'night_emergency');

  // 2. 月初〜月末の日付配列
  const [year, month] = sourceMonth.split('-').map(Number);
  const lastDay = new Date(year, month, 0).getDate();
  const records = [];

  for (let day = 1; day <= lastDay; day++) {
    const date = new Date(year, month - 1, day);
    const dateStr = `${sourceMonth}-${String(day).padStart(2, '0')}`;
    const isWeekend = date.getDay() === 0; // 日曜
    const isHol = isHoliday(date);
    const isHolidayDay = isWeekend || isHol;

    // 夜間枠（365日）
    records.push({
      duty_date: dateStr,
      rotation_type: 'night_emergency',
      area: info.area,
      department: null,
      hospital_id: null,
      facility_name: info.facilityName,
      phone: info.phone,
      start_time: info.nightStart,
      end_time: info.nightEnd,
      note: info.note ?? null,
      source_month: sourceMonth,
    });

    // 昼間枠（休日のみ）
    if (isHolidayDay) {
      records.push({
        duty_date: dateStr,
        rotation_type: 'night_emergency',
        area: info.area,
        department: null,
        hospital_id: null,
        facility_name: info.facilityName,
        phone: info.phone,
        start_time: info.dayStart,
        end_time: info.dayEnd,
        note: info.note ?? null,
        source_month: sourceMonth,
      });
    }
  }

  // 3. バッチINSERT
  const { error } = await supabaseAdmin
    .from('emergency_rotations')
    .insert(records);

  if (error) {
    throw new Error(`生成に失敗しました: ${error.message}`);
  }

  return { count: records.length };
}
```

### 5.4 施設名 → `hospital_id` マッチング仕様

- **完全一致のみ**（`hospitals.name === row.facility_name`）
- 表記揺れ（全角/半角括弧、末尾スペース、「（鼎）」のような所在地表記）は **マッチング対象外** → `hospital_id = NULL` で登録
- 必要なら登録後に管理画面の編集機能で個別に紐付ける運用とする
- 部分一致（LIKE）は採用しない — 誤マッチを避けるため

### 5.5 インポート時のロジック

```typescript
// 疑似コード
async function importEmergencyRotations(formData, sourceMonth) {
  await verifyAdminAuth();

  const file = formData.get('file');
  const rows = await parseFile(file);  // CSV or Excel

  // 1. バリデーション
  const errors = validateRows(rows, sourceMonth);
  if (errors.length > 0) {
    return { success: false, errors };
  }

  // 2. 病院マスタとマッチング
  const { data: hospitals } = await supabaseAdmin
    .from('hospitals')
    .select('id, name');
  const hospitalMap = new Map(hospitals.map(h => [h.name, h.id]));

  const records = rows.map(row => ({
    duty_date: row.duty_date,
    rotation_type: row.rotation_type,
    area: row.area,
    department: row.department || null,
    hospital_id: hospitalMap.get(row.facility_name) ?? null,
    facility_name: row.facility_name,
    phone: row.phone,
    start_time: row.start_time,
    end_time: row.end_time,
    note: row.note || null,
    source_month: sourceMonth,
  }));

  // 3. 既存削除（同じ source_month のみ）
  await supabaseAdmin
    .from('emergency_rotations')
    .delete()
    .eq('source_month', sourceMonth);

  // 4. バッチINSERT
  const { error } = await supabaseAdmin
    .from('emergency_rotations')
    .insert(records);

  if (error) throw new Error(error.message);

  return { success: true, count: records.length };
}
```

## 13. リスクと注意点

### 13.1 データ運用リスク

| リスク | 対策 |
|--------|------|
| 月初までに当番医データを投入し忘れる | ダッシュボードに「来月分登録状況」アラート表示 |

| インポート時に既存月を誤って上書き | 確認ダイアログで `source_month` を明示表示 |

- 既存 `/emergency` ページは**変更しない限り影響なし**
- 既存テーブル群への変更は**ゼロ**
- 管理画面の他ページとは独立しているので干渉なし
